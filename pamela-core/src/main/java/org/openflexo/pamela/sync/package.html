PAMELA Synchronization Package

This package provides real-time collaborative editing capabilities for PAMELA models through message-broker transports (RabbitMQ and MQTT via Artemis). It contains the synchronization layer: transport managers, operation model, serialization, CRDT application logic and helper utilities for identity and property state management.

Overview

The synchronization stack is composed of two complementary parts:

  1. Transport layer (implementations of SyncManager) which publish and consume SyncOperations.
  2. Application layer (SyncEditingContext and CRDT strategies) which apply received operations to the local PAMELA model and produce local operations to broadcast.

Key classes and responsibilities

  • SyncEditingContext

    Main entry point for synchronized editing. It hooks into PAMELA's undo/atomic edit machinery to observe local edits and produce SyncOperations. It also receives remote operations and delegates application to a CRDT strategy. Features include:

    • Registration of local and remote handlers
    • Management of object identities via ObjectIdentityManager
    • Buffering of operations during CREATE to ensure correct ordering
    • State snapshot/restore for late-joining replicas
    • Integration with UndoManager so remote edits are not recorded as local
  • RabbitMQSyncManager and ArtemisMQTTSyncManager

    Concrete SyncManager implementations. They handle connecting to the broker, publishing serialized operations and notifying listeners when messages are received. The RabbitMQ implementation uses AMQP exchanges/queues; ArtemisMQTT uses MQTT topics.

  • SyncOperation

    Immutable value object representing an operation (CREATE, DELETE, SET, ADD, REMOVE, REINDEX, STATE_REQUEST, STATE_RESPONSE). Carries operation id, replica id, vector clock, target object id, property identifier and serialized values.

  • SyncOperationSerializer

    Jackson-based JSON serializer/deserializer used by transport implementations to convert operations to/from wire format (bytes or text).

  • SyncValueSerializer

    Helper that serializes property values. It supports reference serialization for PAMELA proxy objects (object references encoded using their UUID) and allows registering custom serializers for application-specific types.

  • ObjectIdentityManager

    Maintains a global mapping between stable UUIDs and local object instances (proxy objects). Used to resolve references during restore and remote operation application.

  • VectorClock

    Lightweight vector clock implementation used to track causality between operations and help CRDT decision-making.

  • PropertyStateManager

    Maintains per-object property state to support CRDT algorithms and deletion propagation. It stores the last known SET/REINDEX operation per property and applies recursive deletion markers when an object is deleted.

  • CRDT strategy (CrdtLowestIdStrategy, CrdtContext, ICrdtStrategy)

    Pluggable CRDT strategy used to apply remote operations in a conflict-resilient way. The default strategy (CrdtLowestIdStrategy) creates remote objects when needed, applies modifications, and uses simple heuristics (e.g. lowest-id tie-break) for resolution.

  • RemoteOperationHandler

    Functional interface used to register handlers for specific operation types at runtime.

Common workflows

Local edit -> broadcast

  1. User modifies a PAMELA object (atomic edit occurs).
  2. SyncEditingContext intercepts the edit via registered local handlers and builds a SyncOperation.
  3. The operation is serialized with SyncOperationSerializer and published by the configured SyncManager.

Receiving remote operations

  1. Transport receives a message and deserializes it into SyncOperation.
  2. The transport notifies listeners (property change events) and the SyncEditingContext applies the operation via the configured CRDT strategy.
  3. During application, the context marks itself as applying a remote operation to avoid re-broadcast loops and to tag resulting AtomicEdits with the remote replica id.

Usage example (quick)

// Setup
SyncEditingContext context = new SyncEditingContext();
RabbitMQSyncManager mgr = RabbitMQSyncManager.builder()
    .host("localhost")
    .credentials("guest","guest")
    .exchangeName("pamela.sync")
    .routingKey("operations")
    .build();

context.setModelFactory(new PamelaModelFactory(MyModel.class));
context.setSyncManager(mgr);
mgr.connect();

// Create and modify an object: operations will be broadcast
MyModel m = context.getModelFactory().newInstance(MyModel.class);
m.setName("hello");
